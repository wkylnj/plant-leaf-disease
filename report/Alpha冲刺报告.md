#### 过去完成了哪些任务

本周主要完成了项目从零到「训练管线可运行」的基础建设，具体如下。

**（1）数据集落地**

选用 PlantVillage 公开数据集（Mohanty et al., 2016），从 HuggingFace 镜像 `GVJahnavi/PlantVillage_dataset` 下载三个 parquet 文件（合计 812.8 MB），编写 `ml/src/prepare_data.py` 完成格式转换与分层切分：

- parquet 内嵌二进制图像 → ImageFolder 结构的 JPG 文件
- 按 9:1 分层抽样从训练集切出验证集（seed=42，保证每个类别在两个 split 中比例一致）
- 目录名加两位索引前缀（如 `00_Apple_Apple_scab`），保证 `ImageFolder` 的字典序与标签整数序严格对应

最终得到 38 类共 54381 张图像：train 39170 / val 4333 / test 10878。

**（2）数据集体检**

编写 `ml/src/data_audit.py`，自动统计规模、类别分布、图像属性，并产出两张报告用图。体检发现两个必须在建模阶段处理的问题：

- **类别严重不均衡**：最多的 `Orange_Haunglongbing` 有 3966 张，最少的 `Potato_healthy` 只有 110 张，相差 36.1 倍。若模型退化成永远预测最多类，accuracy 仍有 10.1%，但 macro-F1 会接近 0。因此本项目所有实验结果同时报告 accuracy 与 macro-F1。
- **背景高度一致**：抽样网格显示绝大多数图像是单一浅色背景、居中的单片叶子。这正是文献批评 PlantVillage 为「实验室摆拍」的直接证据，也是我们后续要做跨域实验和 Grad-CAM 可解释性实验的立论依据。

**（3）模型工厂**

编写 `ml/src/models.py`，用统一的 `build_model(name, num_classes, pretrained)` 接口封装六种网络：ResNet18、ResNet50、MobileNetV3-Large、ShuffleNetV2-x1.0、EfficientNet-B0、Swin-T。每种网络正确替换分类头，并返回参数量等元信息。

这里踩过一个坑：MobileNetV3 的 `classifier` 是 4 层 `Sequential`（Linear / Hardswish / Dropout / Linear），必须替换索引 `[3]` 而不能整体替换，否则会丢掉 Dropout 层；EfficientNet 则是 2 层，替换 `[1]`。因此代码里对每种模型写死索引，而不是用「遍历找最后一个 Linear」的通用写法——后者在 torchvision 版本变动时会静默替换错层。

**（4）训练脚本**

编写 `ml/src/train.py`，包含分层学习率（骨干 lr×0.1、分类头 lr）、线性 warmup + cosine 退火、标签平滑 0.1、梯度裁剪、混合精度（仅 CUDA 生效）、断点续训。输出目录包含 `config.json`、`history.csv`、`best.pt`、`last.pt`、`summary.json` 和测试集预测结果，便于报告复现。

**（5）手写特征基线**

#### 有哪些收获和疑问

**收获**：

1. **「跑通」和「跑对」是两件事。** 冒烟测试只用 3 个 batch、精度毫无意义，但它验证了数据加载、前向、反向、优化器、保存这一整条链路，让我在真正开训之前就排掉了大部分环境问题。如果直接上全量训练再 debug，代价会大得多。

**疑问**：

1. **预训练权重是否被允许？** 我们使用的是 torchvision 提供的 ImageNet 预训练权重，只替换分类头后微调。这在学术上是标准做法，但课程是否接受「不从头训练」还需要向老师确认。我们已在代码里保留 `--no-pretrained` 开关，若不允许可随时切换，并已准备好两组结果的对比。

### 3.3 手写特征基线实验

在开始训练深度网络之前，我们先用**完全不依赖神经网络**的方法建立了一条基线，目的是量化「ImageNet 预训练学到的参数，究竟比人手设计的特征强多少」。这个实验不需要 GPU，在本地 CPU 上即可完成。

**方法**：162 维人工特征 + LogisticRegression

| 特征组 | 维度 | 内容 |
|---|---:|---|
| HSV 颜色直方图 | 102 | 三通道各 32 bin（归一化为分布）+ 每通道均值/标准差 |
| GLCM 纹理 | 12 | 对比度、相异性、同质性、能量、相关性、ASM，4 方向 × 2 距离取均值与标准差 |
| Gabor 滤波器 | 48 | 4 尺度 × 6 方向，每核取响应均值与标准差 |

**结果**：

| 指标 | 数值 |
|---|---|
| test accuracy | **92.17%** |
| test macro-F1 | **90.43%** |
| 特征维度 | 162 |
| 分类器训练耗时 | **7.7 秒**（CPU） |
| 特征提取耗时 | 1557 秒（CPU 单进程） |
| 多数类基线 | 10.13% |

**最难识别的五个类别**：

| 类别 | F1 |
|---|---:|
| Potato healthy | 0.701 |
| Potato Late blight | 0.761 |
| Tomato Early blight | 0.771 |
| Tomato Late blight | 0.789 |
| Apple Apple scab | 0.812 |

**这个结果说明了三件事**：

1. **PlantVillage 这个任务本身不难。** 162 个手工数字、7.7 秒训练就能到 92%，说明判别信息大量存在于低层视觉统计量中。这也解释了为什么文献里各种网络都能报到 99%——任务太简单，模型容量差异被数据集的简单性掩盖了。**在 PlantVillage 上比精度是没有意义的**，这正是我们项目要论证的核心观点。

2. **剩下 8% 的差距有明确的技术解释。** 最难识别的全是马铃薯和番茄，共同点是病斑局部且小、需要区分斑点的**空间结构**（番茄早疫病的同心轮纹 vs 晚疫病的不规则水渍状）。颜色直方图只能回答「全图有多少褐色像素」，回答不了「褐色像素排成什么形状」。这正是卷积核在局部窗口上滑动的价值。

3. **后续 CNN 的提升可以归因。** 如果 ResNet18 微调能到 98%，那 6 个百分点可以明确归因为**空间结构建模能力**，而不是含糊的「深度学习比较强」。

完整分析见 `ml/artifacts/handcrafted_baseline.md`。

## 四、本次反思

### 做得好的地方

1. **先想清楚再动手。** 在写第一行训练代码之前，先产出了方案文档和施工计划，把「做什么、为什么做、做到什么算完」定下来。这使得后面每一步都有明确的验收标准，没有出现反复返工。

2. **把风险前置。** 在正式训练之前先做冒烟测试，用 3 个 batch 验证整条链路；在建模之前先做数据体检，提前发现类别不均衡。这两个动作各花了不到一小时，但避免了后面更大的损失。

### 不足之处

1. **团队没有真正运转起来。** 这是最严重的问题。本周所有成果均由组长一人完成，另两位队友尚未产生任何提交。作为组长，我在分工之后没有跟进，也没有设定中间检查点，导致「分工」停留在了纸面上。

2. **对零基础的低估。** 我原本以为「装个 Python、跑个脚本」是一天的事，实际上队友在环境配置上就卡住了。这说明我在分配任务时，是按「我会做什么」而不是按「他们能做什么」来分的。

3. **文档写得多，代码跑得少。** 本周产出了五份文档，但正式训练一次都还没跑。文档是为了对齐认知，但如果只有文档没有可运行的东西，就变成了自我安慰。

### 改进办法

1. **把「每天一条 commit」变成硬性要求。** 哪怕只改一个错别字、只加一行注释，也必须提交。这不是为了凑数，而是为了让每个人的进度可见——看不见的进度等于没有进度。

2. **降低第一次动手的门槛。** 不再要求队友「先学完 Python 再看代码」，而是直接给一个 10 分钟能跑完的命令（`python scripts/check_env.py`），让他先看到输出，建立「我能让它跑起来」的信心，再往上加。

3. **组长的工作从「自己做」转向「让别人能做」。** 本周我习惯了自己动手最快，但这在团队项目里是错的。接下来我要做的是把任务拆到「不需要理解原理也能执行」的粒度，并在每一步设置验收点。

4. **下周必须有一次真实的全链路演示。** 从 App 选图到屏幕显示结果，哪怕中间环节用的是假数据，也要先把链路打通。链路不通，各模块做得再好也无法集成。
