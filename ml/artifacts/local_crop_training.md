# E-12 局部裁剪训练：唯一一条真正改变「模型看到什么」的路线，也失败了

**一句话结论**：在已有权重上做局部裁剪微调，跨域从 28.18% 掉到 **22.40%（−5.79pp）**，同域从 99.41% 掉到 98.80%（−0.62pp），作物级从 51.13% 掉到 46.03%（−5.10pp）。这是本轮第六条被证伪的路线，也是**最有价值的一条负结果**——因为它排除了「只要强迫模型看局部就能修好跨域」这个最自然的猜想。

## 为什么这条路线值得单独做

前面五条被证伪的路线（E-10 域适应增强、E-13 测试时适配、E-17 颜色对齐、E-16 叶片定位裁剪、E-11 多模型集成）有个共同点：**都只改变输入或输出的表层统计，没改变模型内部依赖的特征类型**。

E-7 Grad-CAM 的结论是模型看的是「整片叶子的全局统计特征」而非「病斑的局部形态」。那么最直接的推论就是：**训练时只喂局部小块，把全局构图信息破坏掉，模型如果还想学好，就只能依赖病斑的局部纹理与形状**。这是理论上最有可能奏效的一条路，也是唯一一条能真正改变「模型看到什么」的路线。

## 实验设置

| 项目 | 配置 |
|---|---|
| 基座模型 | ResNet18，11.196M 参数，ckpt epoch 11（PV val 0.9954） |
| 局部裁剪 | `RandomResizedCrop(224, scale=(0.15, 0.5), ratio=(0.75, 1.33))` |
| 其他增强 | 只保留水平/垂直翻转，**不用 RandAugment、不用 ColorJitter** |
| 训练轮数 | 3 轮，每轮 200 个 batch（共 38400 张次 ≈ 覆盖全量 39170 张一遍） |
| 学习率 | 骨干 1e-4 / 分类头 1e-3，AdamW，cosine，label smoothing 0.1 |
| 评估 | 同域 PV test 10878 张；跨域 PlantDoc 全量 2920 张（零样本口径） |

**两个实现取舍的理由**：

1. **为什么不用强增强**：这一步要检验的是「看局部」本身的效果。如果同时叠加 RandAugment 和 ColorJitter，两个因素混在一起就分不清是谁起的作用——而 E-10 已经证明颜色扰动单独用是负收益（−2.22pp），混进去只会污染结论。
2. **为什么在已有权重上微调，而不是从零训练 15 轮**：本机纯 CPU，ResNet18 在 224 分辨率强增强下吞吐约 7 img/s，39170 × 15 轮 ≈ 23 小时不可行；Kaggle 的 local-crop kernel 排队 6 小时以上仍未分配机器。短程微调在方法上等价于「用局部裁剪做无监督域适应」，而且不需要目标域标签——这正是它相对 E-14 PlantDoc 微调（需 2920 张标注）的潜在价值。

## 主结果

| 指标 | 微调前（基线） | 微调后 | 变化 |
|---|---|---|---|
| PV test top-1（同域） | 0.9941 | 0.9880 | **−0.62pp** |
| PlantDoc top-1（跨域） | 0.2818 | **0.2240** | **−5.79pp** |
| PlantDoc top-3 | 0.4901 | 0.4418 | −4.83pp |
| PlantDoc 作物级 | 0.5113 | 0.4603 | **−5.10pp** |
| 平均置信度 | 0.4366 | 0.3978 | −3.88pp |

**训练过程**（`localcrop_finetune.json` 的 history）：

| 轮 | train_loss | train_acc | val_top1 | 耗时 |
|---|---|---|---|---|
| 1 | 0.8829 | 0.9445 | 0.9855 | 462s |
| 2 | 0.8082 | 0.9681 | 0.9852 | 542s |
| 3 | 0.7772 | 0.9776 | 0.9905 | 587s |

训练本身是成功的：loss 稳定下降，train_acc 从 94.45% 升到 97.76%，val_top1 回到 99.05%。**模型确实学会了在只看局部的情况下认病**——但它对真实照片的泛化反而更差了。

## 结论

### 结论一：强迫模型看局部，损害而非改善跨域泛化

这是反直觉但可解释的。局部裁剪让模型在训练时只看到叶片的一小块，于是它学到的判别依据变成了「这块小区域的颜色和纹理」。而 PlantDoc 的真实照片里：

- 病斑往往只占叶片的很小一部分，局部裁剪后大多数 patch 是**健康组织**，模型学到的是健康组织的统计量；
- 真实照片的局部 patch 里混着土壤、阴影、其他叶片、背景杂物，这些在 PlantVillage 的局部 patch 里几乎不存在；
- 全局构图（叶片轮廓、居中位置、背景纯净度）在 PlantVillage 里是极强的类别线索，破坏它等于**扔掉了模型最可靠的那部分信息，换来的是更不可靠的局部纹理**。

换句话说：模型依赖全局统计特征**不是缺陷，而是它在 PlantVillage 上能拿到 99% 的正当理由**。强行剥夺这个依据，只会让它退化到更弱的特征上，而这些弱特征在真实照片里漂移得更厉害。

### 结论二：跨域问题的根因不在「注意力范围」，而在「特征本身的域不变性」

六条路线全部证伪后，可以下一个更强的判断：

| 路线 | 改变了什么 | 跨域结果 |
|---|---|---|
| E-10 域适应增强 | 输入的颜色/模糊分布 | −2.22pp |
| E-13 测试时适配 | 推理时的 BN 统计量 / 伪标签 | −6.75pp ~ −30pp |
| E-17 LAB 颜色对齐 | 输入的颜色一阶/二阶矩 | −2.78pp ~ −2.78pp |
| E-16 叶片定位裁剪 | 输入的构图范围 | −3.57pp |
| E-11 多模型集成 | 输出的概率组合 | +0.03pp（无效） |
| **E-12 局部裁剪训练** | **模型看到的空间范围（动了权重）** | **−5.79pp** |

前五条是「改输入/输出」，第六条是「改模型看到什么」。**连动权重都没用**，说明：PlantVillage 预训练出来的特征表示，在真实田间图像上的**判别信息本身就缺失**——不是注意力跑偏了，不是颜色不对齐，也不是统计量漂移，而是「叶片表面在实验室白光下 vs 田间自然光下的成像差异」导致同一病斑呈现出完全不同的像素模式。这个 gap 只能靠**见到目标域的样本**来跨越。

### 结论三：这也正好解释了为什么只有 E-14 微调有效

E-14 PlantDoc 微调（+41.55pp，5/5 折全提升）是唯一大幅有效的路线。它的第 1 轮 val_top1 就到了 59~65%（零样本仅 26~31%），说明**提升主要来自「让模型见到目标域成像风格」本身**，而不是学到了新的病害知识。

对比 E-12：局部裁剪也是「动权重」，但它动权重时看的还是 PlantVillage 的像素分布。**关键在于训练数据的成像条件，不在于训练方式。**

## 对项目的意义

1. **报告里这是一条高价值的负结果**：它把「域适应」这条路彻底封死了——不是「还没调好」，而是「方向本身不对」。这比单纯报告一个 69.73% 的成功数字更有说服力，因为它展示了排除法的完整过程。
2. **产品结论更硬**：模型必须用目标域的图训练（哪怕只有几千张），否则无论怎么改增强、改推理、改注意力范围都修不好。这直接支撑「现场采集数据 → 增量训练」的产品路线。
3. **成本结论**：E-12 花 90 分钟 CPU 换来一个明确的否定答案，比继续在增强函数上试参数划算得多。

## 已知局限

1. 只测了 ResNet18，没测 Swin-T（Swin 的注意力机制不同，局部裁剪的影响可能不一样，但 CPU 上 3 轮微调需约 5 小时）。
2. 只测了 `scale=(0.15, 0.5)` 一组参数，没做尺度扫描（更极端的 0.05~0.2 或更温和的 0.4~0.8 可能有不同结果）。
3. 微调只有 3 轮 × 200 batch，训练不充分；但从 val_top1 已回到 99.05% 看，模型已收敛到局部裁剪这个设定下。
4. 未做「局部裁剪 + PlantDoc 微调」的组合，无法判断局部裁剪在有目标域标签时是否有额外价值。
5. 单次运行，未做多种子重复（CPU 成本限制）。

## 复现

```bash
cd ml
python src/finetune_localcrop.py \
  --run-dir runs/resnet18_224_15ep \
  --epochs 3 --limit-batches 200 \
  --scale-min 0.15 --scale-max 0.5 \
  --num-workers 4
```

约 90 分钟（含前后两次同域 + 跨域评估，各约 2 分钟 / 1 分钟）。
