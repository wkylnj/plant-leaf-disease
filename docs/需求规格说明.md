## 一、引言

### 1.1 目的

本文档定义「叶片医生」安卓 App 的软件需求。读者是：团队成员（照着实现）、课程老师（评估需求分析质量）、未来的维护者。

### 1.2 范围

**本文档覆盖**：安卓客户端的需求（功能、非功能、界面、数据）。
**本文档不覆盖**：服务端实现细节（见 `docs/计划.md` §1）、模型训练细节（见 `docs/方案.md` §4）。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 叶片 | 植物叶子，本系统的输入对象 |
| 病害类别 | 本系统能识别的 38 种「作物 + 病害」组合 |
| Top-3 | 模型给出的概率最高的 3 个候选类别 |
| 置信度 | 模型对 Top-1 结果的概率值（0–1） |
| 假数据模式 | 不连后端、本地生成结果的开发模式（`USE_MOCK=true`） |
| 纠错 | 用户指出识别结果错误的行为 |

## 二、用户画像（v2，基于调研框架重写）

> v1 版本（`docs/方案.md` §2.1）只有 3 个角色标签，没有具体场景。v2 补充「一天中的什么时刻、在什么地方、想解决什么」。

### 2.1 主要用户：李大姐（45 岁，家庭菜园 + 2 亩大棚）

| 维度 | 内容 |
|---|---|
| 身份 | 农村家庭主妇，种 2 亩大棚番茄和自家菜园 |
| 手机 | 千元安卓机，会用微信、抖音、拼多多 |
| 技术水平 | 能装 App、能拍照、能发朋友圈；看不懂设置项，不会看权限弹窗 |
| 典型场景 | 早上 7 点进棚，发现番茄叶子有褐色斑点，掏出手机拍一张，想知道**是不是病、要不要打药、打什么药** |
| 网络 | 棚里信号一般，偶尔 3G |
| 核心痛点 | 以前凭经验，判断错过一次，白打了两次药 |
| 她不会做的事 | 不会看 Top-3 的概率数字、不会选"病害类别"这种专业名词、不会读长文本 |
| 她最想要的一句话 | "这是早疫病，赶紧打药，不然会传染" |

**对她的设计含义**：
- 结果页的**病害名称必须最大最醒目**，概率数字是次要的
- 防治建议要用大白话（"打代森锰锌"而不是"喷施 80% 代森锰锌可湿性粉剂 600 倍液"）
- 不允许出现"请选择病害类别"这种 38 项长列表

### 2.2 次要用户：小陈（21 岁，农学院植保专业大三）

| 维度 | 内容 |
|---|---|
| 身份 | 农学院学生，做过田间实习，认识常见病害 |
| 技术水平 | 高，能看懂置信度、能分辨近似病 |
| 典型场景 | 实习时拍叶子，想快速确认自己的判断对不对；或者做课程作业需要标注 |
| 核心痛点 | 现有识别 App 只给一个答案，错了也不知道错在哪 |
| 她最想要的一句话 | "90% 是早疫病，8% 是晚疫病——你看斑点有没有同心轮纹" |

**对她的设计含义**：
- Top-3 对她**有用**，但必须配「区分特征」说明，否则她也不需要
- 置信度数字可以展示
- 她可能愿意纠错（专业能力强，纠错成本低）

### 2.3 边缘用户：养花的小王（25 岁，办公室白领）

种多肉和绿萝，偶尔叶子发黄。用得少，但会是问卷的主要来源。**不作为主要设计对象**，避免为了他牺牲李大姐的易用性。

### 2.4 反面用户（明确不做）

| 用户 | 为什么不做 |
|---|---|
| 规模化农场（几百亩） | 需要的是无人机巡田、多光谱成像，不是手机拍单片叶子 |
| 科研人员 | 需要的是可导出标注数据、批量处理，超出课程范围 |
| 只想识别"这是什么植物"的人 | 不是病害识别，是物种识别，任务不同 |

## 三、用户故事（14 条，Given/When/Then 格式）

> 格式说明：**作为**〈角色〉，**我想要**〈功能〉，**以便**〈价值〉。
> 验收标准用 Given（前提）/ When（操作）/ Then（结果）写，可直接转成测试用例。

### US-01 拍照识别（Must）

**作为**李大姐，**我想要**拍一张叶片照片就能知道是什么病，**以便**不用再问人、不用瞎打药。

- **Given** 我已打开 App 且相机权限已授予
- **When** 我点「拍照」并拍下一片叶子
- **Then** 3 秒内看到识别结果，结果卡片上病害中文名最大最醒目
- **And** 如果超过 3 秒，显示「正在识别…」并有进度指示
- **And** 如果失败，显示可读的错误原因（"网络不通"而不是"IOException"），并保留我拍的照片

### US-02 相册选图识别（Must）

**作为**李大姐，**我想要**从相册里选一张之前拍好的照片来识别，**以便**在没有信号的地方先拍照、回家再识别。

- **Given** 我在首页
- **When** 我点「从相册选择」并选中一张图
- **Then** 走与 US-01 相同的识别流程
- **And** 如果选的不是图片文件，提示「请选择图片」

### US-03 结果展示：Top-1 突出（Must）

**作为**李大姐，**我想要**一眼看到最主要的结果，**以便**快速决定要不要打药。

- **Given** 识别成功返回 Top-3
- **When** 结果页渲染完成
- **Then** Top-1 的中文病害名以全页最大字号显示（≥28sp）
- **And** Top-1 的置信度以百分比显示，但字号小于病害名
- **And** 作物名单独一行显示（"番茄 · 早疫病"）

### US-04 结果展示：Top-3 候选（Should）

**作为**小陈，**我想要**看到其他两个候选和它们的概率，**以便**在自己拿不准时参考。

- **Given** 识别成功返回 Top-3
- **When** 我查看结果页
- **Then** Top-2、Top-3 以列表形式显示在 Top-1 下方，每项含中文名 + 概率
- **And** 如果 Top-2 概率 < 5%，该行以浅灰显示（表示可忽略）
- **And** 点击任一候选可展开该病害的简要说明（区分特征）

### US-05 低置信度警告（Should）

**作为**李大姐，**我想要**在模型没把握时被明确告知，**以便**不因为一个错误答案打错药。

- **Given** Top-1 置信度 < 60%
- **When** 结果页渲染
- **Then** 结果卡片顶部显示橙色警告条：「模型不太确定，建议再拍一张或咨询农技员」
- **And** 该警告的视觉权重高于病害名

### US-06 免责声明（Must）

**作为**项目团队，**我想要**在界面上明确声明"结果仅供参考"，**以便**尽到告知义务、避免误导用户。

- **Given** 用户首次进入 App
- **When** 首页加载完成
- **Then** 首页底部显示免责声明文字：「本工具结果仅供参考，不能替代专业诊断。用药请遵医嘱或咨询农技员。」
- **And** 该文字常驻可见（不是弹窗、不可关闭）

### US-07 识别历史（Should，原 Must 降级待验证）

**作为**李大姐，**我想要**回看之前识别过的记录，**以便**对比同一棵植物的变化。

- **Given** 我至少识别过一次
- **When** 我点首页右上角的历史图标
- **Then** 看到按时间倒序的识别记录列表，每条含缩略图 + 病害名 + 时间
- **And** 点击任一条进入详情页（US-08）
- **And** 如果从未识别过，显示空态引导：「还没有识别记录，去拍一张吧」

> **降级理由**：原方案把 F4（识别历史）列为 Must。但这需要本地持久化（Room 或文件存储），成本不低。调研问题 C4 专门验证"用户是否真的会回看"。若 C4 显示多数人"不需要"，则降为 Could 或砍掉。

### US-08 识别详情页（Should）

**作为**李大姐，**我想要**点开一条历史记录看到完整信息，**以便**回忆当时的情况。

- **Given** 我在历史列表页
- **When** 我点某一条记录
- **Then** 进入详情页，显示：大图 + 病害名 + 置信度 + Top-3 + 识别时间 + 反馈状态
- **And** 详情页可发起纠错（US-09）

### US-09 纠错反馈（Should）

**作为**小陈，**我想要**告诉 App 它识别错了，**以便**帮助模型改进，也让我自己记下正确答案。

- **Given** 我在结果页或详情页
- **When** 我点「识别不对」
- **Then** 弹出底部弹层，第一屏只问「正确的是什么？」并给出两个选项：「我知道正确病害」/「我也不确定」
- **And** 选「我知道」时，先选作物（5 个按钮），再选该作物下的病害（4–8 个按钮），**不出现 38 项长列表**
- **And** 选「我也不确定」时，只记录「识别错误」这一事实，不要求给正确答案
- **And** 提交后显示「感谢反馈」，并把该记录标记为「已纠错」

> **设计依据**：假设 H9（从 38 类里选绝大多数人放弃）→ 所以必须两级筛选。若调研显示用户连选作物都不愿意，则降级为只记录"对/错"。

### US-10 模型信息页（Could）

**作为**小程（好奇的用户）或老师，**我想要**看到当前用的是哪个模型、准确率多少，**以便**判断结果可信度。

- **Given** 我在首页
- **When** 我点右上角菜单或底部免责声明
- **Then** 进入「关于」页，显示：App 版本、模型名称（如 ResNet18）、模型参数规模、训练数据集、测试集准确率、Top-3 覆盖的作物种类
- **And** 显示一句技术说明：「本模型在实验室条件下训练的 PlantVillage 数据集上准确率 99.4%，在真实田间照片上可能显著下降」

### US-11 网络异常处理（Must）

**作为**李大姐，**我想要**在网络不好时知道发生了什么、能重试，**以便**不白等。

- **Given** 我点了识别但网络不可用
- **When** 请求超时（10 秒）
- **Then** 显示「网络好像不通，检查一下再试」，并提供「重试」按钮
- **And** 我拍的照片仍然显示在页面上（不丢失）
- **And** 重试时不需要重新拍照

### US-12 权限拒绝处理（Must）

**作为**李大姐，**我想要**在拒绝相机权限后仍能使用相册选图，**以便**不因为一次误点就卡死。

- **Given** 我拒绝了相机权限
- **When** 我点「拍照」
- **Then** 显示说明「需要相机权限才能拍照。你也可以从相册选一张已有的照片」，并提供「去设置」和「从相册选」两个按钮
- **And** 不出现无限弹权限请求

### US-13 清空历史（Could）

**作为**李大姐，**我想要**一键清空所有识别记录，**以便**释放空间或保护隐私。

- **Given** 我在历史页且至少有 1 条记录
- **When** 我点「清空」
- **Then** 弹出确认对话框：「确定清空全部 __ 条记录？此操作不可恢复。」
- **And** 我确认后才真正删除；取消则不变

### US-14 反馈提交（Should）

**作为**项目团队，**我想要**把用户的纠错数据传回服务器，**以便**统计模型在真实场景的错误分布。

- **Given** 用户提交了纠错
- **When** 网络可用
- **Then** 调用 `POST /feedback`，携带 `request_id`、`is_correct`、`true_label`（可选）
- **And** 提交失败时本地暂存，下次启动时重试（不阻塞用户）
- **And** 用户不需要登录、不需要提供任何个人信息

## 五、非功能需求

| 类别 | 要求 | 验证方式 |
|---|---|---|
| **性能** | 端到端识别（拍照→出结果）≤ 3 秒（4G 网络、服务器空闲） | 在模拟器 + 本机后端实测计时 |
| **性能** | App 冷启动 ≤ 2 秒 | `adb shell am start -W` 测 TotalTime |
| **性能** | 首页列表滚动不掉帧（≥50 fps） | 模拟器 GPU 渲染分析 |
| **可用性** | 首次使用无需教程即可完成一次识别 | 找 3 个没用过的人实测，观察是否卡住 |
| **可用性** | 所有错误提示为中文、可读、可操作 | 代码走查 |
| **兼容性** | Android 8.0（API 26）及以上 | 模拟器 API 26 / 35 双测 |
| **兼容性** | 屏幕宽度 360dp–480dp 自适应 | 模拟器改分辨率测试 |
| **可靠性** | 网络失败不丢失已拍照片 | 断网测试 |
| **可靠性** | 连续识别 20 次不崩溃 | 压力测试 |
| **安全性** | 不收集任何个人身份信息 | 代码走查 + 抓包确认 |
| **安全性** | 图片仅用于识别，服务端不长期保存 | 服务端代码走查 |
| **可维护性** | 假数据模式可在不改代码的情况下切换 | `USE_MOCK` 编译开关验证 |
| **包体积** | APK ≤ 20 MB | 构建产物检查（当前 16.4 MB） |
| **无障碍** | 正文对比度 ≥ 4.5:1 | 颜色计算 |
| **无障碍** | 所有可点击元素 ≥ 48dp | 布局检查 |
