# CORAL 特征对齐 + 多任务学习：PlantVillage → PlantDoc

## 一句话

实现已完成、冒烟通过、链路打通，但**一条决定性的闭式实验给出了负面先验**：在冻结特征上
直接做经典 CORAL 重着色（把目标域协方差搬成源域的），跨域准确率 **26.09% → 24.74%
（−1.35pp）**，而同一批特征用目标域标签训线性探针能到 **60.19%**。这说明 30pp 的跨域
掉点主因**不是二阶统计量漂移**，而是特征与目标域语义的映射关系变了——这正是 CORAL
在原理上管不到的部分。因此我对这条路线能否提升的判断已从「+1.5~+4pp」下调为
**「大概率无效或小幅负收益，最好情况 +1~2pp」**，理由与证据见下文。

同时实现过程中发现了一个会让整个实验变成假阴性（错误地得出没有效果）的坑：按论文原式
`||Cov(S)−Cov(T)||²_F / (4d²)` 算出的 CORAL 梯度只有病害 CE 的 1/261，μ=0.1/0.5/1.0
三档实际都落在噪声里。脚本因此加了梯度自校准，否则跑完 15 轮会得到「CORAL 无效」的
错误结论——虽然结论方向可能与闭式实验一致，但理由完全不同。


## 方法

### 双头多任务

骨干（ResNet18，去掉原分类头）输出 512 维特征，接两个独立线性头：

| 头 | 类别数 | 损失 | 权重 |
|---|---|---|---|
| 病害头 | 38（PlantVillage 全集） | CE + label smoothing 0.1 | 1.0 |
| 作物头 | 14 | CE + label smoothing 0.1 | λ = 0.4 |

作物标签从文件夹名解析（`00_Apple_Apple_scab` → `Apple`）。作物名有多词的
（`Corn_maize`、`Cherry_including_sour`、`Pepper_bell`），按长度降序前缀匹配，
口径与 `analyze_errors.CROP_KEYS` 一致。

辅助任务的作用：给共享特征加一个**域无关的粗粒度语义轴**。作物类别在两个域里
是对应的（PlantDoc 也有 Apple/Corn/Tomato 等），所以这个约束不会把源域特征往
目标域不需要的方向拉，反而阻止 CORAL 把特征对齐到「两个域都退化成同一团」。

### CORAL

对齐源域与目标域特征的**协方差矩阵**（二阶统计量）：

```
Cov(X) = (X − mean(X))ᵀ (X − mean(X)) / (n − 1)
L_coral = ||Cov(S) − Cov(T)||²_F / (4 d²)
```

d=512。实测数学正确性：手算与实现结果完全一致（差 0.0），同批数据自比为 0，
纯平移（协方差不变）为 ~1e-33，缩放 2 倍时按理论值放大。

**必须 fp32 计算**：autocast 会把特征降成 fp16，而协方差是二阶量，512×512 的
累加误差会被平方放大。实现里 CORAL 在 `autocast(enabled=False)` 块内算，两次
前向则在同一个 autocast 块内完成（保证源/目标走完全相同的数值路径，否则 CORAL
测到的是精度差异而不是分布差异）。

### 总损失

```
L = CE_病害 + λ · CE_作物 + μ · L_coral
```

### 梯度自校准（关键，非论文原式）

这是本次实现最重要的发现。实测（resnet18，batch 32，首个 batch）：

| 损失项 | 数值 | 梯度范数 |
|---|---|---|
| 病害 CE | 3.71 | 5.32 |
| 作物 CE | 2.70 | 5.20 |
| CORAL | 0.0049 | **0.0204** |

CORAL 梯度只有任务损失的 **1/261**。μ=0.5 时 CORAL 只占总梯度 **0.19%**，
μ=1.0 也只有 0.38%——三档 μ 全在噪声级，跑完 15 轮会得到「CORAL 无效」的结论，
但那是缩放伪影（数值尺度造成的假象），不是方法本身失效。

原因：除以 4d² 让 loss 数值与 d 无关，但 d=512 时把量级压到了 1e-3；而 CE 在
训练初期是 3.6。论文里 μ 取 0.5~1.0 是在**未归一化**的 CORAL 下调的，直接套用
公式会掉进这个坑。

脚本提供 `--coral-autoscale`：在首个 batch 上实测 `||g_task||` 与 `||g_coral||`，
按 `系数 = ratio × ||g_task|| / (||g_coral|| × μ_max)` 放大，使 **μ 达到 μ_max 时
CORAL 梯度正好占总梯度的 `ratio`**（默认 5%）。按 μ_max 归一化而非按当前 μ，
是为了让 ramp 期间占比从 0 线性升到 ratio，与 `coral_warmup_epochs` 的意图一致
（早期特征剧变，强行对齐等于给移动靶画圈）。

只测一次、全程固定：每步重测会让有效权重随 batch 抖动，等于给 CORAL 加噪声。

关闭该选项时退回论文原式（μ 就是字面权重），便于与文献对照。

## 实现细节

- **脚本**：`ml/src/train_coral_mtl.py`，自包含（约 1150 行），不 import 仓库其它模块，
  因此可以单独拉到 Kaggle 跑。`parse_known_args` 兼容 Kaggle 塞进来的 `-f kernel.json`。
- **目标域加载**：`ImageFolder` 直接读 `ml/data/raw/plantdoc/train`，标签读出来但
  **在训练循环里丢弃**（`x_t, _y_t = next(tgt_iter)`），loss 里不出现任何目标域标签。
  这是无监督域适应的定义，不是「自觉地不看」。
- **增强**：目标域用与源域**完全相同**的强增强（RandomResizedCrop 0.6~1.0、
  HFlip、VFlip p=0.2、RandAugment 2×9、ColorJitter、RandomErasing p=0.25）。
  理由：如果目标域用弱增强，CORAL 会把「增强差异」也当成域差异去对齐。
- **优化**：AdamW(weight_decay=0.05)，分层学习率（骨干 lr×0.1），warmup 2 轮 +
  cosine 退火到 1%，grad clip 1.0，label smoothing 0.1——全部与 `train_colab.py` 一致，
  保证对比的是方法差异而不是训练配置差异。
- **模型选择**：只看**源域验证集**准确率存 best.pt。用目标域指标选模型会破坏
  无监督假设（等于偷看标签）。
- **checkpoint 兼容**：`ck["model"]` 存标准键名（骨干 + 病害头在 `fc.*`），
  可被 `models.build_model(name, 38)` 直接 `load_state_dict(strict=True)`，
  已验证全部键匹配。因此 `eval_crossdomain.py` 能直接评估本脚本的产物，口径与基线一致。
- **消融开关**：`--no-coral`（只多任务）、`--no-mtl`（只 CORAL）。

## 冒烟结果（真实数字，CPU）

环境：torch 2.6.0+cpu，无 GPU。全部为小规模冒烟，**不能作为准确率结论**。

### CORAL 数学验证

| 检查 | 结果 |
|---|---|
| 手算 vs 实现 | 0.08191156947661318 vs 0.08191156947661318，差 **0.0** |
| 同批自比 | 0.0 |
| 纯平移（协方差不变） | 3.28e-33 |
| 缩放 2 倍 | 0.4150（理论 9× 单域协方差差，符合） |
| n=1 退化 | 0.0（不产生 NaN） |
| 梯度 | grad_s=0.0711, grad_t=0.0630，全部有限 |

### 训练冒烟

`--epochs 2 --limit-batches 30 --batch-size 32`（30 batch × 32 = 960 张/轮）：

| 轮 | total | 病害 CE | 作物 CE | CORAL | 训练 acc | 目标域置信 | 耗时 |
|---|---|---|---|---|---|---|---|
| 1 | 4.5966 | 3.5651 | 2.5393 | 0.00472 | 8.44% | 0.076 | 240s |
| 2 | 4.1006 | 3.1990 | 2.1697 | 0.00505 | 21.04% | 0.123 | 276s |

三项 loss 同向下降，CORAL 稳定在 5e-3 量级（与理论量级吻合），说明梯度确实在流动。
该次运行的放大系数在旧语义下报 ×13.39；改成按 μ_max 归一化后同一 batch 会报
×26.78（μ_max=0.5 → μ_eff_max=13.39），两种语义下「CORAL 占总梯度 5%」的
实际效果相同，只是报数基准不同。

目标域置信度从 0.076 升到 0.123，说明特征在朝「对目标域更有判别力」的方向移动，
但幅度很小，2 轮远不足以判断。**注意：这项指标在闭式实验后已不足以支撑乐观结论**，
见下一节。

### 链路验证

- `eval_crossdomain.py` 能直接读本脚本的 best.pt（strict 加载全键匹配，前向输出 38 维）
- 冒烟 checkpoint 上跑通完整评估，产出 `crossdomain.json` + `crossdomain_preds.csv`
- 消融开关 `--no-coral` / `--no-mtl` 均能跑通，loss 项正确置零
- 自校准语义验证：`--coral-autoscale` 报「放大 ×26.78，μ 达到 μ_max=0.5 时 CORAL
  梯度占总梯度 5.0%（μ_eff_max=13.39）」——放大系数看着大，是因为原始 CORAL
  梯度极小（0.0204），按构造最终只占任务梯度的 5%

## 决定性证据：闭式 CORAL 实验（`ml/src/coral_closed_form.py`）

在做全量训练之前，先用**不训练任何网络**的闭式实验回答「CORAL 在这批特征上到底有用吗」。
用基线 `runs/resnet18_224_15ep/best.pt` 的 512 维特征（fc 换成 Identity）：

- 源域：PlantVillage val 分层抽样 2500 张
- 目标域：PlantDoc train 有映射的 2668 张（随机一半用于拟合无标签协方差，另一半评估）
- 分类器统一用 LogisticRegression(C=1.0, max_iter=3000)

| 实验 | 做法 | top-1 | 相对 A |
|---|---|---|---|
| A | 源域特征训 → 目标域测（无对齐，对照） | **26.09%** | — |
| B | 两边各自白化到单位协方差 | 23.69% | **−2.40pp** |
| B2 | **经典 CORAL 重着色**：`Xt' = (Xt−μt)·Ct^(-1/2)·Cs^(1/2) + μs` | 24.74% | **−1.35pp** |
| C | 目标域标签训 → 目标域测（上界，非无监督） | 60.19% | +34.10pp |
| D | 源域+目标域特征联合训练（上界，需目标标签） | 60.64% | +34.55pp |

三个关键读数：

1. **经典 CORAL 变换是负收益**（−1.35pp）。这是 CORAL 训练时梯度所逼近的目标，
   闭式版已经是它的「完美实现」——如果完美实现都掉点，用梯度去逼近它不会更好。
2. **各自白化更差**（−2.40pp）。说明这批特征的二阶结构里含有**有用的域特有信息**，
   强行抹平是在删信号，不是在去偏移。
3. **60.19% vs 26.09%** 的 34pp 缺口无法用二阶统计量解释。目标域标签训的探针
   （同维度、同分类器、同特征）能到 60%，说明特征里**含有**判别信息，只是
   「哪一维对应哪个病害」的映射在跨域时变了。CORAL 只对齐 P(feature) 的二阶矩，
   不改变映射关系，所以原理上补不上这 34pp。

补充一个独立读数：对**全部** 2668 张 PlantDoc 特征做 3 折交叉验证的逻辑回归探针，
准确率 **58.13%**（std 1.57pp）。与 C 的 60.19% 口径不同（C 是半集训半集测），
但结论一致——特征本身可分，瓶颈在跨域映射。

> 方法学说明：B2 用的是「拟合半集 / 评估半集」的无标签协方差，符合无监督设定；
> C/D 用到目标域标签，**只作为定位瓶颈的诊断上界**，不能当作可交付结果。

这个结论也解释了为什么之前六条路线全部失败：它们都在试图修「输入的统计量」或
「输出的决策边界」，而这个任务的病根在**条件分布 P(y|x) 变了**（同一病害在野外
长成另一个样子），属于需要目标域标签或强语义先验才能修的问题。


## 对能否提升跨域准确率的判断

**判断：大概率无效或小幅负收益（−2 ~ +1pp）；最好情况 +1~2pp（作物级 +2~4pp）。
不建议把它当作主力路线。**

这个判断基于闭式实验的直接证据，不是文献外推：

**决定性理由（负面）**
1. **CORAL 变换的完美实现本身就是负收益**（−1.35pp）。训练时 CORAL loss 的梯度
   就是在逼近这个变换，闭式版没有估计噪声、没有优化不收敛的问题，是最理想情形。
   理想情形都掉点，训练版没有理由更好。
2. **34pp 的缺口无法用二阶统计量解释**。同一批特征，目标域标签训探针能到 60.19%，
   源域训只有 26.09%。差的是「特征 → 病害」的映射，不是特征的分布形状。
   CORAL 不改变映射，原理上补不上。
3. 这与项目已有的机制结论一致：跨域掉点主因是条件分布 P(y|x) 变化（实验室白背景
   的叶子 vs 野外复杂背景的叶子），属于需要目标域标签或强语义先验才能修的问题。
   六条路线全部失败不是巧合，而是同一个病根的不同表现。

**仍保留的一点空间（为什么不是 −5pp 那种确定失败）**
1. 闭式实验是**冻结特征 + 线性分类器**。端到端训练时 CORAL 会改变骨干，
   特征可能移动到「既可分又对齐」的更好位置，这是闭式实验测不到的自由度。
2. 多任务作物头是**独立于 CORAL 的增益来源**。作物级基线 51.13%，辅助任务直接
   监督这个更粗的语义轴，λ=0.4 的作物头即使没有 CORAL 也可能带来作物级 +2~4pp。
   这部分收益与 CORAL 无关，是消融实验要分离出来的。
3. 文献里 DeepCORAL 在 Office-31 上有 2~5pp，说明方法本身在**同类型偏移**
   （成像风格差异、但语义映射稳定）下有效。本项目不满足这个前提，但不排除
   端到端训练能挤出一点。

**最可能的结局**：top-1 在 26%~29% 之间（基线 28.18%），作物级小幅提升。
如果消融显示 `--no-coral`（只多任务）优于完整配置，就确认了 CORAL 是负担、
收益全部来自作物头。

**建议的验证顺序**（如果还要花 GPU 时间）：
1. 先跑 `--no-coral`（只多任务）单配置。这是最便宜、最可能有效的一档。
2. 再跑 μ=0.5 完整配置。若不如第 1 步，直接放弃 CORAL，把结论写进
   `crossdomain_experiments.md` 的失败清单。
3. 不值得做 μ=0.1/1.0 的扫描——闭式实验已经说明方向不对，调参救不回来。

**如果一定要在跨域上拿分**，已有证据指向更强的骨干（Swin-T 多分辨率平均
37.50%）或有监督微调（69.73%），而不是继续在无监督特征对齐上投入。
