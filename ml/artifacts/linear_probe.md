# E-03 线性探针：跨域失败完全在特征层，分类头没有责任

**一句话结论**：冻结骨干、只训练一个线性分类器，同域和跨域指标**几乎完全等于端到端模型**（同域甚至略高 0.14~0.25pp，跨域差异在 ±0.65pp 内）。这说明训练出来的分类头对最终精度**几乎没有额外贡献**——99% 的同域精度全部来自骨干的特征表示，28% 的跨域失败也完全在特征层。**换分类头、加正则、做校准都救不了跨域。**

## 为什么要做这个实验

前面几轮实验都在问「怎么把跨域提上去」，但一直没回答一个更基础的问题：

> 掉点是因为**骨干学到的特征本身就不对**，还是因为**最后那层分类头过拟合了 PlantVillage**？

这两者的修法完全不同。如果是分类头过拟合，换头、加 dropout、做温度校准、调 label smoothing 都可能有效；如果是特征本身的问题，那只能动骨干（微调、换预训练目标、换架构）——而这正好对应 E-14 PlantDoc 微调有效（+41.55pp）、E-12 局部裁剪训练无效（−5.79pp）这两条结果。

线性探针（linear probe）是分离这两者的标准做法：**冻结骨干、只训练一个线性分类器**。如果线性探针在跨域上也崩，说明特征本身已经不可分，与头无关。

## 实验设置

| 项目 | 配置 |
|---|---|
| 骨干 | ResNet18 / Swin-T / MobileNetV3-Large，全部 `eval()` + `requires_grad=False` |
| 特征 | 全局平均池化后的向量（ResNet18 512 维、Swin-T 768 维、MobileNetV3 1280 维） |
| 探针 | `LogisticRegression(max_iter=2000, C=1.0, class_weight="balanced")`，前置 `StandardScaler` |
| 探针训练集 | PlantVillage **train**（39170 张） |
| 同域评估 | PlantVillage **test**（10878 张） |
| 跨域评估 | PlantDoc 全量（2920 张，27 类映射，零样本） |
| 端到端对照 | 直接读已有的 `summary.json` / `crossdomain.json`，不重复推理 |

实现要点：`get_feature_extractor()` 把分类头替换成 `nn.Identity`——ResNet18 是 `model.fc`、MobileNetV3 是 `model.classifier[3]`、Swin-T 是 `model.head`。特征提取时如果输出还是多维（Swin-T 的 token 序列），做全局平均池化压成一维。

## 主结果

| 模型 | 特征维度 | 端到端同域 | **探针同域** | 差值 | 端到端跨域 | **探针跨域** | 差值 |
|---|---|---:|---:|---:|---:|---:|---:|
| ResNet18 | 512 | 0.9941 | **0.9966** | **+0.25pp** | 0.2818 | **0.2839** | +0.21pp |
| Swin-T | 768 | 0.9962 | **0.9979** | **+0.17pp** | 0.3493 | 0.3428 | −0.65pp |
| MobileNetV3-Large | 1280 | 0.9948 | **0.9962** | **+0.14pp** | 0.2582 | 0.2582 | 0.00pp |

探针的 top-3 与作物级：

| 模型 | 探针跨域 top-1 | 探针跨域 top-3 | 探针跨域作物级 |
|---|---:|---:|---:|
| ResNet18 | 0.2839 | 0.4952 | 0.5048 |
| Swin-T | 0.3428 | 0.5589 | 0.5291 |
| MobileNetV3-Large | 0.2582 | 0.4774 | 0.5034 |

探针训练耗时 0.8~3.1 秒（sklearn 在 39170×512~1280 的特征矩阵上收敛很快），特征提取耗时 411~2017 秒（Swin-T 最慢，与 E-3 效率实测的 3.21× 延迟倍数一致）。

## 结论

### 结论一：分类头对精度的贡献接近于零

三个模型的线性探针**全部不低于端到端**（+0.14 / +0.17 / +0.25pp）。这是一个很强的结论：

- 15 轮训练学到的分类头，其判别能力**完全可以被一个线性分类器复现**；
- 也就是说，ResNet18 在 PlantVillage 上拿到 99.41%，靠的**不是**分类头学会了什么复杂的决策边界，而是骨干输出的特征**本身就已经线性可分**；
- 那 15 轮训练真正在做的事情，是**把骨干的特征空间整形到线性可分**，分类头只是最后画了一条线。

这个结论对报告有价值，因为它把「模型能力」定位到了具体位置：**特征表示**，不是分类器。

### 结论二：跨域失败 100% 在特征层，与分类头无关

如果分类头过拟合了 PlantVillage，那么换成一个在冻结特征上重新训练的线性分类器（正则化更强、类别权重平衡、完全没见过 PlantDoc）应该能改善跨域表现。实际结果是：

- ResNet18：+0.21pp（噪声水平）
- Swin-T：−0.65pp（噪声水平，甚至略差）
- MobileNetV3：0.00pp（完全一致）

**没有任何改善。** 这排除了「分类头过拟合」这个假设，把责任完全归到骨干特征上。

### 结论三：与 E-12 / E-14 的结果形成完整闭环

三条实验从不同角度指向同一个结论：

| 实验 | 动了什么 | 跨域结果 | 说明 |
|---|---|---|---|
| E-03 线性探针 | 只换分类头（骨干冻结） | ±0.65pp（无效） | 头不是瓶颈 |
| E-12 局部裁剪训练 | 动骨干，改变输入空间范围 | −5.79pp | 动骨干但方向错 |
| E-14 PlantDoc 微调 | 动骨干，改变输入成像条件 | **+41.55pp** | 动骨干且方向对 |

**关键在于「动骨干时喂什么数据」，不在于「动哪里」或「怎么动」。**

- 换头（E-03）→ 完全无效，因为瓶颈不在头；
- 动骨干但喂同源数据的局部块（E-12）→ 更差，因为学到的是更弱的同源统计量；
- 动骨干且喂目标域数据（E-14）→ 大幅提升，因为终于让特征见到了目标域的成像风格。

### 结论四：Swin-T 的特征优势也在骨干层

Swin-T 的线性探针跨域 34.28%，比 ResNet18 的 28.39% 高 5.89pp，比 MobileNetV3 的 25.82% 高 8.46pp——**与端到端的排名完全一致**（34.93% / 28.18% / 25.82%）。这说明 Swin-T 的优势不是「头学得更好」，而是**骨干学到的特征对成像条件更鲁棒**（全局自注意力机制能建模更长程的空间关系，对局部光照变化不敏感）。代价是 27.55M 参数（ResNet18 的 2.46 倍）和 3.21× CPU 延迟。

## 对项目的意义

1. **明确排除了「优化分类头」这条路**：以后不用再试 dropout、label smoothing 调参、温度校准、换 ArcFace/CosFace 之类的头设计——线性探针证明这些都不会影响跨域。
2. **把资源集中到正确的地方**：要提升跨域，只能改骨干的特征表示，而唯一有效的手段是让骨干见到目标域数据（E-14）。
3. **给报告一个清晰的能力定位**：模型的能力全部在特征表示上，这也解释了为什么 Grad-CAM 看到的是「全局统计特征」而不是「病斑局部形态」——那是骨干学到的表示本身的属性。
4. **轻量模型的部署价值更明确**：MobileNetV3 的特征维度是 1280（三者最高），线性探针同域 99.62%（三者中最低但差距很小），跨域 25.82%（最低）。它的优势纯粹在参数量和延迟，不在表示质量。

## 已知局限

1. 只用了逻辑回归一种探针，没试线性 SVM、kNN、MLP 探针对照（结论方向不太可能改变，但 MLP 探针可能略高）。
2. 特征提取用的是 `build_transforms(img_size, train=False)`，即 resize+center crop，与训练时的验证集一致；没试过用训练增强的特征做探针。
3. 只测了 224 分辨率，没测探针在 320/352 分辨率下的表现（E-15 已证明端到端提分辨率有效，探针大概率也有效）。
4. 未做显著性检验（单次运行，但三个模型的差异方向高度一致，偶然性很低）。
5. Swin-T 的特征提取耗时 2017s，是全流程最慢的一环，如果要扩展到六模型需注意时间成本。

## 复现

```bash
cd ml
python src/linear_probe.py \
  --runs resnet18_224_15ep swin_t_224_15ep mobilenet_v3_large_224_15ep \
  --img-size 224 --batch-size 64 --num-workers 4
```

约 50 分钟（Swin-T 特征提取占大头）。
