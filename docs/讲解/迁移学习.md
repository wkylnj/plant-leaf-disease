# 迁移学习：从 1000 类到 38 类

> 本文回答一个问题：**原模型能识别 1000 类，怎么变成专门识别叶片病害的？**
> 答辩时如果被问到"你们的模型是不是调包"，照这篇讲。

---

## 一、先纠正一个说法：不是"退化"

"退化"暗示模型变弱了。实际发生的是**换任务**，不是能力下降。

原模型的能力是"把一张图映射到 1000 个英文名词里最像的那个"。这个能力对叶片病害任务**完全没用** —— 因为 1000 类里没有"苹果黑腐病"这个选项，最接近的可能是 `daisy`（雏菊）或 `leaf beetle`（叶甲），横竖都是错的。

所以那 1000 类的输出层不是被削弱，是**被整个扔掉，换成新的**。

---

## 二、ResNet18 的两段结构

```
输入图片 [3, 224, 224]
    ↓
┌────────────────────────────────────┐
│ conv1 → layer1 → layer2 → layer3   │  ← 特征提取器（骨干 / backbone）
│ → layer4 → avgpool                 │     权重来自 ImageNet，保留
│                                    │     学到的是：边缘、纹理、颜色斑块、
│                                    │     形状、物体部件
└────────────────────────────────────┘
    ↓
  特征向量 [512]
    ↓
┌────────────────────────────────────┐
│ fc: Linear(512 → 1000)             │  ← 分类头（head）
└────────────────────────────────────┘     权重来自 ImageNet，丢弃
    ↓                                      换成 Linear(512 → 38)，随机初始化
  38 个分数（logits）
    ↓
  softmax → 38 个概率
```

**关键点：那个 `[512]` 维的特征向量，是模型对"这张图长什么样"的描述。**

它对 ImageNet 的 1000 个类一无所知，它只知道怎么把像素压缩成 512 个有意义的数字。至于这 512 个数字代表什么，取决于后面接什么头：

- 接 `Linear(512, 1000)` → 它描述的是"像狗还是像车"
- 接 `Linear(512, 38)` → 它描述的是"像苹果黑腐病还是番茄早疫病"

**同一段特征，接不同的头，就是不同的任务。** 这就是为什么换一层就能换任务。

## 三、代码里怎么换（六个模型各不同）

| 模型 | 代码 | 原输出 | 换后 |
|---|---|---|---|
| resnet18 | `model.fc = nn.Linear(512, 38)` | 512→1000 | 512→38 |
| resnet50 | `model.fc = nn.Linear(2048, 38)` | 2048→1000 | 2048→38 |
| mobilenet_v3_large | `model.classifier[3] = nn.Linear(1280, 38)` | 1280→1000 | 1280→38 |
| shufflenet_v2_x1_0 | `model.fc = nn.Linear(1024, 38)` | 1024→1000 | 1024→38 |
| efficientnet_b0 | `model.classifier[1] = nn.Linear(1280, 38)` | 1280→1000 | 1280→38 |
| swin_t | `model.head = nn.Linear(768, 38)` | 768→1000 | 768→38 |

**两个容易写错的地方：**

1. **MobileNetV3 的 `classifier` 是 4 层 Sequential**（Linear → Hardswish → Dropout → Linear）。
   必须替换 `[3]`，不能整个换掉 —— 整个换掉等于把 Dropout 删了，模型会过拟合。
2. **EfficientNet 的 `classifier` 是 2 层**（Dropout → Linear），所以是 `[1]`。

**为什么不写通用代码自动找最后一层**：模型版本一升级，结构可能变，自动找会静默替换错层，
而且不报错。写死索引至少升级时会直接崩，能立刻发现。

实现在 `ml/src/models.py` 的 `build_model()`。

## 四、换掉的到底是什么

原 `fc` 层：`Linear(512, 1000)` = 512×1000 + 1000 = **513000 个参数**，输出"狗、车、键盘……"1000 个分数。

新 `fc` 层：`Linear(512, 38)` = 512×38 + 38 = **19494 个参数**，输出 38 个病害分数。

**旧的 51.3 万个参数被直接丢弃**，新层随机初始化 —— 所以它一开始什么都不会，输出全是噪声。
训练的作用就是让它从噪声变成"会认 38 种病害"。

**前面所有层（约 1114 万参数）的权重原封不动保留。** 这就是迁移学习的全部含义：
保留通用视觉能力，只更换最后的分类映射。

---

## 五、为什么这 512 维特征对叶片有用

因为在 ImageNet 上学到的能力 —— 检测边缘、检测纹理、检测颜色突变、检测斑块 ——
**恰好也是识别病斑需要的能力**。

病斑在图像上是什么？是**颜色异常的局部区域 + 边界不规则的形状 + 特定纹理**。
这些正是卷积层在 ImageNet 上学得最透的东西。

所以各层的复用程度不同：

| 部分 | 复用程度 | 原因 |
|---|---|---|
| 浅层卷积（conv1, layer1） | 几乎 100% | 边缘、颜色梯度是任何视觉任务共通的 |
| 中层卷积（layer2, layer3） | 高 | 纹理、斑块，与病斑特征高度重叠 |
| 深层卷积（layer4） | 中 | ImageNet 学的是"物体部件"（狗耳朵、车轮），需要转向"病斑形态" |
| 分类头 | 0% | 类别完全不同，必须重训 |

## 六、训练时到底在训练什么

默认**所有层都更新**（不冻结），但更新幅度不同：

| 部分 | 初始状态 | 训练中的作用 | 学习率 |
|---|---|---|---|
| 浅层卷积 | 已学会看边缘 | 几乎不动 | 3e-5（`lr*0.1`） |
| 深层卷积 | 已学会看物体部件 | 明显调整 | 3e-5（`lr*0.1`） |
| 新分类头 | **随机初始化，全是噪声** | 从零学，变化最大 | 3e-4（`lr`） |

代码在 `ml/src/train.py` 的 `build_optimizer()`：

```python
groups = [
    {"params": backbone_params, "lr": lr * backbone_scale},  # 3e-5
    {"params": head_params,     "lr": lr},                   # 3e-4
]
```

**如果给所有层同一个大学习率会怎样**：浅层那些宝贵的"看边缘"能力被 15 轮训练冲掉，
模型退化成接近从零训练，精度反而更低。这是微调最经典的错误。

**典型症状**：前 3 个 epoch 精度先涨后崩 —— 骨干被破坏，而新头还没学起来。

## 七、一个类比

想象你招了一个**在 1000 种物体上练过眼力的质检员**。他没见过病害，
但他极其擅长"看出这块表面和周围不一样"。

现在你要他做的是：判断这片叶子是 38 种病里的哪一种。

你不需要教他"什么是边缘""什么是颜色差异"—— 他早会了。你只需要：

1. 给他一本 38 种病害的图册（= 换分类头）
2. 让他看 5.4 万张标注好的样本（= 训练）
3. 告诉他"原来的判断标准要调整，别老想着找狗耳朵"（= 微调深层）

**他不会因为换了任务就变笨，他的眼力还在。** 这就是迁移学习。

## 八、能验证这件事的便宜实验（可进报告）

**线性探针（linear probe）**：把 5.4 万张叶片图全部过一遍骨干网络，只取那 512 维特征，
然后用 `sklearn.linear_model.LogisticRegression` 在特征上训一个分类器。

| 结果 | 说明 |
|---|---|
| 能到 90%+ | 特征本身已经足够好，深度微调只是把它推到 98% —— 强证据 |
| 只有 60-70% | 特征需要大幅调整，说明域差异比想象的大 |

**成本**：特征提取约 10 分钟（CPU），逻辑回归几秒。
**价值**：这是"为什么迁移学习有效"的直接证据，而且是自己测的，不是引用别人的。

命令示例（待实现 `ml/src/linear_probe.py`）：

```bash
python src/linear_probe.py --model resnet18 --data-root data/processed/plantvillage
```

## 九、如果老师不允许用预训练

`train.py` 已内置开关，不用改代码：

```bash
python src/train.py --model resnet18 --no-pretrained
```

`--no-pretrained` 会让 `weights=None`，所有层随机初始化。

**预期后果**（这是有文献支撑的，不是猜）：

| 模型 | 微调 | 从零训练 |
|---|---|---|
| ResNet18 | ~98% | ~90%（要 100+ epoch 才追得上） |
| MobileNetV3 | ~97% | ~85% |
| ViT-B/16 | ~98% | **~60%，基本训不动** |

ViT 那行是关键：它没有卷积的"局部性"先验，需要海量数据才能学会"相邻像素相关"这件事。
5.4 万张图对它来说太少。**从零训练会让对比变成"谁更依赖数据"，而不是"谁结构更适合部署"**，
核心结论就跑偏了。

## 十、答辩可能被问的三个问题

**Q：你们的模型是不是直接调包？**
A：结构和预训练权重来自 torchvision，但任务适配、数据整理、六模型对比实验、
跨域测试、效率实测都是我们做的。核心贡献是回答了"手机上该用哪种模型"这个问题，
不是发明网络结构。

**Q：为什么不用从零训练？**
A：5.4 万张图对 ViT 这类模型太少，从零训练会欠拟合，对比就失去意义。
我们另外跑了一组对照（微调 vs 从零），量化了预训练带来的提升是 +X 个百分点。

**Q：换个数据集还能用吗？**
A：不能直接用。这正是我们做跨域实验（E2）的原因 —— PlantVillage 是实验室摆拍，
真实照片上精度会掉到 30-60%。我们在报告里明确写了这个限制，App 里也有免责声明。
