## 1. 这份手册怎么用

### 1.1 三条铁律

1. **一个任务没做完，不要开下一个。** 任务之间有依赖，跳着做会在联调时全部返工。
2. **每个任务都必须留下"证据"**：一个文件、一张截图、一次 git 提交、一段能跑的命令输出。没有证据 = 没做。
3. **看不懂的代码不许合进主分支。** 你可以让 AI 写，但你必须能用自己的话讲清"这段在干什么"。讲不清就回去问，不要装懂。

### 1.2 卡住了怎么办

按顺序试：

1. 读报错信息的**最后一行**（前面都是调用栈，没用）。
2. 把报错原文复制给 AI，同时说清"我在做哪个任务、上一步做了什么、期望是什么"。
3. 卡超过 **2 小时**，在群里说一声，换任务做。不要一个人耗一天。

## 2. 我们要做的东西长什么样

### 2.1 一句话

**用手机拍一张作物叶子的照片，系统告诉你这是什么病，并把这次识别记录下来。**

### 2.2 完整链路（大白话版）

```
① 用户在手机上点"拍照"
        ↓
② 照片通过 WiFi 发到我们自己的服务器（一台电脑就行）
        ↓
③ 服务器上的模型看一眼这张图，算出"38 种病里最像哪 3 种"
        ↓
④ 结果发回手机，显示成"番茄晚疫病 87%"
        ↓
⑤ 用户如果觉得不对，点"结果有误"，选正确的病名
        ↓
⑥ 这条反馈存进数据库，以后可以用来改进模型
```

### 2.3 为什么不用"手机自己算"

手机自己算（端侧推理）听起来更高级，但要处理模型压缩、算子兼容、不同芯片适配——三个人都是零基础，这条路大概率卡死在第 3 天。

**我们选服务器算**：手机只负责拍照和发请求，技术难度从"集成推理引擎"降到"发一个网络请求"。这是理性的工程取舍，报告里要写明理由。

### 2.4 系统由哪几块组成

```
┌─────────────┐   HTTP    ┌──────────────────┐
│  安卓 App    │ ────────→ │  后端服务器       │
│  （拍照/显示）│ ←──────── │  （FastAPI）      │
└─────────────┘   JSON    └────────┬─────────┘
                                   │
                          ┌────────┴────────┐
                          ↓                 ↓
                   ┌────────────┐   ┌────────────┐
                   │  模型       │   │  数据库     │
                   │ （ONNX）    │   │ （SQLite）  │
                   └────────────┘   └────────────┘
                          ↑
                   ┌──────┴───────┐
                   │  训练脚本     │
                   │ （Colab GPU） │
                   └──────────────┘
```

**四块东西，对应三个人：**

| 块 | 干什么 | 谁负责 |
|---|---|---|
| 模型 | 认叶子病害 | A（王楷宇） |
| 后端 | 收照片、调模型、存数据库 | B |
| 安卓 App | 拍照、发请求、显示结果 | C |
| 界面设计 | 决定 App 长什么样 | C（可全员评审） |

## 3. 名词速查表

> 遇到不懂的词回来查这里。每条都尽量用"人话"解释。

### 3.1 数据相关

| 词 | 人话解释 |
|---|---|
| **数据集** | 一堆带答案的图片。我们的数据集叫 PlantVillage，5.4 万张叶子照片，每张标好了是什么病。 |
| **类别 / class** | 一种病就是一个类别。我们有 38 个类别。 |
| **train / val / test** | 训练集（用来学）/ 验证集（用来调参、看有没有过拟合）/ 测试集（最后只测一次，用来报成绩）。**绝对不能拿 test 调参**，否则成绩是假的。 |
| **标签 / label** | 这张图的正确答案。是一个整数，0–37，对应 38 个类别名。 |
| **类别不均衡** | 有的病 3966 张图，有的病只有 110 张。模型会偷懒专挑多的类猜。 |
| **数据增强 / augmentation** | 把训练图随机裁剪、翻转、调色，人为造出更多样本，防止模型死记硬背。 |
| **域偏移 / domain shift** | 训练图是实验室拍的（白背景、光照均匀），实际用的时候是田间拍的（杂乱背景、逆光）。模型在后者上会崩。这是我们项目的核心问题。 |

### 3.2 模型相关

| 词 | 人话解释 |
|---|---|
| **神经网络 / CNN** | 一个函数，输入图片像素，输出 38 个分数。由很多层"卷积"堆起来。 |
| **卷积 / convolution** | 拿一个小窗口（比如 3×3）在图上滑动，每滑一次算一次加权和。用来找边缘、斑点、纹理。 |
| **参数量 / params** | 模型里有多少个可调的数字。ResNet18 有 1119 万个。 |
| **预训练 / pretrained** | 别人已经在 1000 类图片（ImageNet）上训好的权重。我们拿过来改改用在叶子上，比从零训快得多、准得多。 |
| **微调 / fine-tune** | 拿预训练模型，换掉最后一层，再用我们的数据接着训。**我们做的就是微调，不是从零训练。** |
| **分类头 / head** | 模型的最后一层，把特征变成 38 个分数。ResNet18 的原来叫 `fc`，是 `Linear(512, 1000)`，我们换成 `Linear(512, 38)`。 |
| **骨干 / backbone** | 分类头前面的所有层。负责把图片变成一串特征数字。 |
| **epoch** | 把整个训练集完整看一遍叫一轮。我们计划看 15 轮。 |
| **batch** | 一次喂给模型几张图。我们一次喂 32 或 64 张。显存不够就调小。 |
| **loss** | 损失，衡量"模型答得有多错"。训练就是想办法让它变小。 |
| **accuracy** | 准确率，答对的比例。 |
| **macro-F1** | 每个类各算一个 F1 分数，然后取平均。**类别不均衡时必须看这个**，因为 accuracy 会被大类带偏。 |
| **混淆矩阵** | 一张 38×38 的表，看模型把"A 病"错认成"B 病"多少次。用来找易混类。 |
| **过拟合** | 训练集上 99%，测试集上 70%。模型在背答案。 |
| **Grad-CAM** | 一种可视化：画出模型看图时"眼睛盯在哪"。如果热力图画在叶子外面，说明它在靠背景猜。 |
| **ONNX** | 一种模型文件格式。PyTorch 训出来的模型转成 ONNX 后，可以在不装 PyTorch 的机器上跑，部署更方便。 |

### 3.3 工程相关

| 词 | 人话解释 |
|---|---|
| **git** | 代码的存档工具。每次改动存一个"快照"，可以回退、可以看谁改了什么。 |
| **commit** | 一次存档。要有说明，比如 `feat: 新增预测脚本`。 |
| **branch / 分支** | 并行的开发线。`main` 是稳定版，`dev` 是开发版，各人再开自己的分支。 |
| **clone** | 把远程仓库整个下载到本地。 |
| **push / pull** | 把本地提交推到远程 / 把远程的拉下来。 |
| **API / 接口** | 服务器对外提供的一组"窗口"。比如 `/predict` 就是"给我一张图，我还你结果"的窗口。 |
| **HTTP / 请求** | 手机和服务器说话的协议。 |
| **JSON** | 一种数据格式，长这样：`{"label": "番茄晚疫病", "prob": 0.87}` |
| **FastAPI** | 一个 Python 的 Web 框架，写后端接口用的。自带一个 `/docs` 页面可以直接测试接口。 |
| **SQLite** | 一个文件就是一个数据库，不用装服务器。适合我们这种小项目。 |
| **multipart** | 上传文件用的 HTTP 格式。手机传照片就用这个。 |
| **端口 / port** | 一台电脑上不同服务的门牌号。FastAPI 默认用 8000。 |
| **Gradle** | 安卓项目的构建工具。负责把一堆源码编译成 APK 安装包。 |
| **APK** | 安卓安装包文件。 |
| **Compose** | 安卓现在的界面写法，用代码直接描述界面，不用写 XML。 |
| **模拟器 / AVD** | 电脑上模拟的安卓手机。我们用的是 Pixel 6 / Android 15。 |
| **adb** | 电脑和安卓设备（真机或模拟器）通信的命令行工具。 |

## 4. 三个人怎么分工

### 4.1 三条主线并行，在联调点汇合

```
        A 算法线                    B 后端线                 C 安卓线
           │                          │                        │
   11-21  训模型（Colab）        建 FastAPI 骨架          建 Compose 工程
           │                          │                        │
   11-22  出结果 + 导出 ONNX      假模型跑通 /predict      拍照 + 上传
           │                          │                        │
           └────────────┬─────────────┴────────────────────────┘
                        ↓
                  11-22 晚 首次联调（用假模型）
                        ↓
   11-23  真模型替换         接口稳定              界面成型 + 截图
           └────────────┬─────────────────────────┘
                        ↓
                  11-23 晚 端到端跑通
                        ↓
   11-24  统稿 + 提交报告
```

**关键设计：B 和 C 不等 A 的模型。** B 先用"假模型"（不管收到什么都返回均匀概率）把接口跑通，C 立刻能联调。A 训完把真模型换进去，B 和 C 的代码一行不用改。

这叫**接口先行**，是软件工程课要考的核心概念之一，报告里值得写一段。

### 4.2 各自主责与交叉备份

| 人 | 主责 | 交叉备份 | 必须能讲清（答辩会被问） |
|---|---|---|---|
| **A 王楷宇** | 模型训练、实验、报告统稿、项目管理 | 后端接口设计 | 六个模型为什么这么选、跨域为什么崩、macro-F1 怎么读 |
| **B** | 后端服务、数据库、部署 | 安卓网络层 | 一张图从上传到返回经过哪几步、数据存在哪 |
| **C** | 安卓客户端、界面设计 | 后端接口联调 | App 有几个页面、拍照后发生什么、网络失败怎么处理 |

**为什么要有交叉备份**：零基础团队最大的风险不是"不会"，而是"一个人请假项目就停"。每块必须有第二个人能顶上，哪怕只是能看懂日志。

### 4.3 分工的三个原则

1. **按"块"分，不按"天"分。** 不要今天你写后端明天我写后端，那样谁都讲不清。一个人负责一块，从头到尾。
2. **每块必须有独立可验收的产出。** 不能出现"我做了一半，等他做完才能验收"。
3. **报告里每个人的章节必须本人写。** 特别是"困难与收获"，这是老师判断你有没有真参与的依据。

### M-04 · Colab 跑通 ResNet18 ⭐🔴

**目标**：得到 `runs/resnet18_224_15ep/summary.json`，里面 `test_acc ≥ 0.95`。

**前置**：P-06（能登录 Colab）。

> **更新（2026-11-21）**：我们已经不用浏览器了，改用 Google 官方 **Colab CLI**，
> 在终端里开 T4 会话。好处是不用手动点菜单、断线不影响远端训练、能脚本化排队。
> 下面两种方式都给出，**推荐方式 A**。

#### 方式 A：Colab CLI（我们实际用的，推荐）

1. **装 CLI**（只装一次）：
   ```powershell
   pip install google-colab-cli
   colab --version      # 应为 0.8.0
   ```
   官方 README 说只支持 Linux/macOS，但实测 Windows 上除 `colab ssh`/`colab repl`
   外都能正常用。

2. **授权**（只做一次）。跑：
   ```powershell
   python scripts/colab_login.py
   ```
   按提示在浏览器打开链接。**关键：授权页面必须把所有权限复选框都勾上（点「全选」）。**
   只勾前几项会导致缺 `colaboratory` 权限，token 存不进去，每次命令都要重新授权。
   授权码一次性、约 10 分钟过期，不能复用。

3. **开 T4 会话**：
   ```powershell
   colab new -s train --gpu T4
   colab status -s train      # 应显示 Hardware: T4 / Status: IDLE
   ```

4. **准备数据**（第一次要，约 5 分钟）：
   ```powershell
   $env:PYTHONUTF8='1'
   python scripts/colab_launch.py --session train --prepare-only
   ```
   完成后远端 `/content/data/plantvillage` 应有 train 39153 / val 4350 / test 10878。

5. **测吞吐**（可选，1 分钟，确认 GPU 真的在跑）：
   ```powershell
   python scripts/colab_launch.py --session train --bench 200
   ```
   正常应看到 `img_per_s` 在 100 以上。我们实测 116.8 img/s。

6. **正式训练**（15 轮，约 90 分钟）：
   ```powershell
   python scripts/colab_launch.py --session train --model resnet18 `
       --epochs 15 --img-size 224 --batch-size 64 --num-workers 2 `
       --run-name resnet18_224_15ep
   ```
   用 nohup 分离进程跑，本地断线不影响。

## 10. 常见卡点与自救

### 10.1 环境类

| 现象 | 原因 | 解法 |
|---|---|---|
| `python: 无法将"python"项识别为...` | Python 没装或没加 PATH | 重装 Python，勾选 "Add Python to PATH" |
| `ModuleNotFoundError: No module named 'torch'` | 依赖没装 | `pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu` |
| PowerShell 中文变问号 | 编码不是 UTF-8 | 先跑 `$env:PYTHONIOENCODING='utf-8'` |
| `cv2.imread` 返回 `None` | 路径含中文 | 用 `np.fromfile` + `cv2.imdecode` |
| git push 报 `Permission denied (publickey)` | SSH key 没配 | 改用 HTTPS + token，或按 GitHub 文档配 SSH |

### 10.2 训练类

| 现象 | 原因 | 解法 |
|---|---|---|
| loss 不降 | 学习率太小或太大 | 试 1e-3 / 1e-4 / 3e-5 三档 |
| loss 变 `nan` | 学习率太大或梯度爆炸 | 降 lr，确认 `grad_clip` 生效 |
| train 99% / val 70% | 过拟合 | 加增强、加 weight_decay、减 epoch |
| val 比 train 高 | 正常（train 有增强，val 没有） | 不用担心 |
| test_acc 只有 0.3 | 标签顺序错位 | 检查目录名索引前缀和 `classes.json` |

### 10.3 安卓类（降级方案）

**判定线：11-22 22:00。**

如果这时 App 还装不上模拟器，按顺序降级：
