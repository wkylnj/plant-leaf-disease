# 测试时适配（test-time adaptation）：PlantVillage → PlantDoc

## 一句话

三种无标签适配方法（BN 统计重估 / TENT / 伪标签自训练）在两个模型上都**没有超过零样本基线**，
最好的组合也只是把损失从 −2.4pp 到 −5.6pp 之间徘徊；BN 重估反而稳定掉 6pp，TENT 在 lr=1e-3 下
直接崩塌到 3%。结论是：本例的跨域掉点不是「统计量漂移」或「决策边界不够尖锐」，
靠无标签的测试时适配补不回来。

## 评估协议

- **适配数据**：PlantDoc **train** split，映射后 2668 张，按类别轮转抽 **700 张**，**不使用任何标签**。
  代码层面由 `ImageOnly` 包装器把 `y` 丢掉，适配循环里只有 `for x in loader`，不存在「靠自觉不看标签」。
  用 700 张而非全量是时间预算所限（纯 CPU，全量一个 epoch 约 5 分钟/方法）。用 700 张而不是 1000 张，是因为
  两个模型 × 5 种方法在 16 线程 CPU 上实测要 26 分钟，取 700 张把总量压到 22 分钟。
- **评估数据**：PlantDoc **test** split，**252 张**（27 类）。标签只在评估时用于算指标。
- **基线**：同一 test split、同一 checkpoint、不做任何适配，走的是 `eval_crossdomain.evaluate` 同一段前向代码，
  保证「提升/下降」不是实现差异造成的。
- 每个方法都从**同一份原始 checkpoint 重新开始**，方法之间没有顺序污染；每个方法适配 1 个 epoch。
- 超参：TENT Adam lr=1e-3（另加一组 lr=1e-4 对照）；伪标签阈值 0.7、微调 lr=1e-4、AdamW；
  输入 224×224，batch 32，纯 CPU（Ryzen 7 7840HS，16 线程，torch 2.6.0+cpu）。

> 注意：本文基线与 `artifacts/crossdomain.md` 里的 28.18% / 25.82% **不可直接比较**。
> 那两份数字是在 PlantDoc `split=all`（2920 张，含 train+test）上算的；本文为了和小样本适配实验
> 严格区分，只在 252 张的 `test` 上评估，所以基线看起来更高（33.73% / 32.14%）。两者不是同一批样本。

## 三个观察

**1. BN 统计重估：稳定掉点，且是「变差」不是「没变化」。**
两个模型的 top-1 各掉 6.75pp / 5.95pp，作物级掉 7.94pp / 9.52pp，平均置信度从 0.44→0.36、
0.47→0.22。置信度一起塌，说明不是「统计量挪了一点、分类头还算能跟上」，而是重估后的特征
本身变得**更不可分**了：分类头是在源域统计量下训出来的，把每层激活强行归一化到目标域分布，
等于给分类头喂了它从没见过的特征尺度。PlantDoc train 里混着 27 类、复杂背景、多叶片，
这些全局统计量并不是「干净的目标域特征偏移」，不能指望它把域差距抹平。

**2. TENT：lr=1e-3 崩塌，lr=1e-4 不崩但也降点。**
lr=1e-3 时 top-1 只剩 3.17%（低于随机 3.7%），平均置信度 0.9993 —— 模型把所有样本推向同一个类，
是熵最小化的典型退化解（把错误预测也变得极度自信）。这**不是实现 bug**：把 lr 降到 1e-4 后，
同一个实现不再崩塌（置信度回到 0.52 / 0.56，top-1 0.2976 / 0.2897），说明崩塌是步长 × 熵目标
共同导致的，而不是代码写错。但即便不崩，lr=1e-4 仍然是 −3.97pp / −3.17pp，没有收益。
mobilenet 的作物级 0.6151 比基线 0.6111 高 0.4pp，但病害级 top-1 反而低 3.17pp ——
换句话说它只是学会了「更保守地认作物」，这正是 TENT 在标签分布不同（PlantDoc 27 类 vs 源域 38 类）
时的已知短板：熵最小化会往「大类」上收缩。

**3. 伪标签自训练：几乎无效。**
阈值 0.7 只留下 99 张 / 80 张（占 700 张的 14% / 11%）—— 跨域基线本身只有 33%，
模型对自己的目标域预测很没把握，能过阈值的样本太少，而且里面还混着错标签。1 轮微调后
top-1 各降 2.38pp / 5.56pp。换句话说，在源域准确率 99%、目标域 33% 的情况下，
伪标签的「信噪比」太低，自训练是拿错标签强化错误。

## 结论

- **适配是否有效**：无效。2 个模型 × 5 种配置（含 lr 对照）共 10 组适配结果，**0 组超过零样本基线**。
  最好的两组是伪标签自训练（resnet18 −2.38pp）和 TENT lr=1e-4（−3.17pp / −3.97pp），
  仍在噪声量级（252 张，±1 张 = 0.40pp）之上但方向是负的。
- **提升多少**：0。没有一组为正。
- **代价多少**：单次适配 55–177s（纯 CPU，700 张 1 epoch），其中 TENT 类要反传，比纯前向的
  BN 重估贵 1.5–2 倍；评估每次 15–38s。若部署时每次换环境都要重跑一遍，代价可接受；
  若要逐样本在线适配（每张图都要更新），这个量级完全不可行。
- **为什么无效**：这三类方法修的都是「特征分布偏移 / 决策边界不尖锐」，
  而本项目跨域的主要矛盾是**特征本身不对**——模型在 PlantVillage 上学到的是「纯色背景 + 居中单叶」
  下的纹理，到 PlantDoc 的多叶横排、过曝、逆光图上，底层卷积响应就已经错了，
  在错的响应上重估统计量或压熵，只是把错的东西变得更整齐。这个判断与项目里另一条线
  （`artifacts/beta_model_update.md` 的域适应增强训练被证伪）是一致的：源域数据层面的增强
  和无标签的目标域统计对齐，都动不到「真实田间图长什么样」这个根上。

## 建议的下一步

1. 不再往无标签 TTA 上投入。若必须提升跨域，需要**少量目标域标注**做微调（哪怕每类 5–10 张），
   或者换**域泛化训练**（多风格合成背景、更强的颜色/几何扰动），而不是测试时适配。
2. 如果继续做 TTA，唯一还值得试的是「逐类/逐batch 的 BN 统计 + 只调分类头偏置」这类
   改动面极小的方案，并且必须先解决 TENT 的崩塌（例如加熵的置信度筛选、只用高置信样本更新）。
3. 无论哪条路，PlantDoc test 只有 252 张，结论容易被 ±2pp 的噪声左右；建议先把 PlantDoc
   的 2920 张做成交叉验证（k 折），否则任何 <2pp 的改进都无法区分于噪声。

## 必须写明的局限

1. **这是 transductive 设定**：适配阶段看过了目标域的无标签图片（虽然不看标签，代码层面也拿不到）。
   **如果完全不允许接触目标域数据**（例如只有一张图、拿到就得出结果、或数据合规不允许留存），
   BN 重估 / TENT / 伪标签自训练**都不适用** —— 它们的前提就是「手上先有一批目标域未标注数据」。
   这一点不写清楚，本文的数字会被误读成「跨域问题已解决」。
2. 适配集是从 PlantDoc train 的**已映射类别**里抽的，筛选时用了文件夹名（不用标签，
   但等于知道目标域有哪些类），严格说是「已知目标域类别集合」的设定。
3. 只适配了 700 张（全量 2668 张的时间约 3.8 倍）。BN 统计量对样本量敏感，
   全量重估有可能改变 BN 那一行的结论（TENT 与伪标签的结论不受影响，它们的主要问题是目标函数本身）。
4. 只跑 1 个 epoch、1 组超参（TENT 额外测了 2 个 lr），没有对阈值、适配集大小、batch 组成做搜索。
   本文的结论是「这套默认配置有没有用」，不是「这类方法的上限」。
5. PlantDoc test 252 张，1 张 = 0.40pp，小于 ±2pp 的差异不应过度解读。
